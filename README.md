# 震相合议室（Phase Room）

单机、无外部服务的多台站 P/S 震相拾取复核应用。Java 17 + Spring Boot 3 + SQLite，
前端为原生 HTML/CSS/Canvas/JavaScript，不依赖任何 CDN 或第三方前端资源，无需 Docker。

## 运行

需要 JDK 17，并保证 `java` 在 PATH 上（仓库 `gradle.properties` 固定
`org.gradle.java.home`，Gradle 本身也可由更高 JDK 启动）。

安装阶段（跳过测试）：

    ./gradlew build -x test

验收：

    ./gradlew test
    ./gradlew bootRun --args='--server.address=127.0.0.1 --server.port=5234'

打开 http://127.0.0.1:5234 即可看到“震相合议室”。首次进入会自动载入固定虚拟数据；
也可点击“载入固定虚拟数据”或调用 `POST /api/demo/seed?force=true` 重新播种。

SQLite 数据库默认写入 `./data/phaseroom.db`（已在 `.gitignore` 中忽略），
重启后解释、冻结快照、分支与撤销历史继续可用。

## 领域与版本

- 台站元数据、速度模型、拾取目录各自带独立版本；波形片段内容（SHA-256）只增不改。
- 每个解释（interpretation）在创建时钉住台站版本表、波形轨道版本表、模型 ID 与拾取
  目录版本；冻结时再写入不可变 `frozen_bundle`。之后台站海拔新增版本不会改变冻结结论，
  `GET /api/interpretations/{code}/replay` 始终按钉住的版本重算残差。
- 波形同内容片段按（轨道、内容哈希、起始时间、采样率、钟偏）去重，重复导入仅累加
  `received_count` 与来源回执；新内容片段才推进轨道版本。
- 缺口与重叠由相邻片段在时间轴上的关系确定性计算；不等采样率逐片段保留；削顶自动检测
  或可在导入时显式声明。
- 拾取支持移动、极性（+/-/?）、置信区间半宽、候选合并、判噪声；每次动作写入
  `action_event`，保存前/后镜像，可逐步撤销。

## 残差、权重与模型比较

- 走时按分层模型的直线射线数值积分，震源深度、台站海拔、震中距（haversine）均参与。
- 观测到时 = 拾取时间 + 覆盖片段的采样时钟偏移 + 解释级校时修正。
- 权重为来源、置信区间、削顶、缺口邻近、校时修正五个独立因子之积，因子逐项在接口返回。
- 模型比较规则：只要存在残差在窗口（默认 5 秒，可用 `phaseroom.window-seconds` 调整）
  之外的采用拾取，模型即被一票否决，不会仅因平均残差更小而获胜；其后按加权平均绝对
  残差、普通平均、窗口外数量、模型代码的确定性顺序裁决。逐台站预测差/观测差/权重来源见
  `POST /api/interpretations/{code}/station-diffs`。

## 校时冲突与冻结

冻结前按各台站采用的 P 拾取计算校正后先后次序。若校时修正使相对次序反转，则阻止冻结，
返回全部冲突对以及“最小冲突台站集合”：该集合基于最长不下降子序列（LNDS，允许同时刻
并列），规模为 n - LNDS，删除后剩余台站次序不再反转。

## 分支与重放

冻结解释可复制为开放分支，完整复制拾取、校时修正与撤销事件，并可替换速度模型。
`GET /api/interpretations/{code}/replay` 同时返回冻结残差与按钉住版本重算的残差并断言
逐行一致。

## 自动化测试

`src/test/java/com/gsb/phaseroom` 下的固定虚拟数据测试覆盖：首页标题、不等采样率、
缺口边界、重叠/削顶、内容去重与回执累计、波形新版本、校时修正、置信区间、权重来源、
模型窗口否决、确定性平局、冻结冲突与最小冲突集合、撤销/合并重放、台站海拔新版本后的
冻结重放、分支替换模型与撤销历史保留。
